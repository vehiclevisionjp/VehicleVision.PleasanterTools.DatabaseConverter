# ライセンス

## 既定

AGPL-3.0-or-later。`LICENSE` に本文、`Directory.Build.props` の `PackageLicenseExpression` に SPDX 式を置いている。

## デュアルライセンスにするとき

商用公開で AGPL と商用のデュアルライセンスにする場合は、次を済ませてから公開する。Questionnaire（`VehicleVision.PleasanterTools.Questionnaire`）が実例。

1. **権利を確認する。** 自社が全コードの著作権を持っていること。外部から貢献を受けるなら CLA（コントリビューターライセンス同意書）で再許諾を受ける。Questionnaire の `CLA.md`、`.github/workflows/cla-check.yml`、`.github/cla/` を参考にする
2. **Pleasanter 本体を取り込んでいないこと。** 本体の著作権は自社に無く、取り込むと商用側を提供できない。`scripts/reference-isolation-check.sh` が通ること
3. **依存が寛容ライセンスだけであること。** MIT / BSD 系 / Apache-2.0。フォントのみ SIL OFL 1.1 も可。GPL・AGPL・LGPL の依存が無いことを `NOTICE` と `packages.lock.json` で確認する
4. **ライセンス文書を足す。** `LICENSING.md`（デュアル提供の説明）と `LICENSE-COMMERCIAL.md`（商用条件）を置く
5. **メタデータを切り替える。** `Directory.Build.props` の `PackageLicenseExpression` を外し、`PackageLicenseFile` で `LICENSING.md` を指す。NuGet は `LicenseRef-*` を含む式を受け付けない。`package.json` の `license` と `NOTICE` の SPDX 行も更新する
6. **規約を更新する。** `.github/copilot-instructions.md` の規約 6 と 8 に、デュアル提供であることと、取り込むと商用側を提供できなくなる理由を書き、`scripts/sync-agents.sh` を実行する

AGPL のまま公開する間は、1 から 6 は不要。ただし規約 8（寛容ライセンスの依存のみ）は、後からデュアルにできるよう常に守る。

# リリース手順

## 版

版の単一情報源は `Directory.Build.props` の `VersionPrefix`。セマンティックバージョニングに従い、1.0.0 未満は互換を保証しない。

## 手順

1. `develop` で `VersionPrefix` を上げ、`master` へ PR を出してマージする
2. Actions の「リリースタグ作成」を `master` から実行する。最初は `dry_run` のまま版だけを検証する
3. 問題なければ `dry_run` を外して実行する。必須チェックの成功を確認してから、GitHub App のトークンで `vX.Y.Z` タグを作る
4. タグを契機に「Release」ワークフローが、検証、配布 ZIP と SHA-256 の作成、dotnet tool の NuGet パッケージ作成、GitHub Releases と nuget.org への公開を行う

`vX.Y.Z-rc.1` のようにハイフン付きの版はプレリリースとして公開する。

## nuget.org への公開（dotnet tool）

CLI を dotnet tool として nuget.org へ公開する。GitHub Releases の配布 ZIP とは別の配布経路で、どちらもタグ（`vX.Y.Z`）を契機に `release.yml` が出す。

| 項目 | 値 |
| --- | --- |
| パッケージ ID | `VehicleVision.PleasanterTools.DatabaseConverter` |
| コマンド名 | `database-converter` |
| 形 | RID 非依存（framework-dependent）の単一パッケージ。.NET 10 ランタイムが要る |
| 同梱 | CLI と Core（Core は単体では公開しない）、依存 DLL、README・`LICENSING.md`・`LICENSE`・`LICENSE-COMMERCIAL.md`・`NOTICE` |

利用者の導入は次のとおり。

```bash
dotnet tool install -g VehicleVision.PleasanterTools.DatabaseConverter
database-converter --help
```

### nuget.org の準備（初回。管理者の作業）

公開は **Trusted Publishing**（OIDC。長期の API キーは持たない）。次を整える。**Claude などのエージェントは、nuget.org と Trusted Publishing の設定を触らない。**

- nuget.org の Trusted Publishing に、次のポリシーを登録する

  | 項目 | 値 |
  | --- | --- |
  | Package Owner | 組織 `vehiclevisionjp` |
  | Repository Owner | `vehiclevisionjp` |
  | Repository | `VehicleVision.PleasanterTools.DatabaseConverter` |
  | Workflow File | `release.yml` |
  | Environment | 空 |
  | Scopes | Push new packages and package versions |
  | Glob | `VehicleVision.PleasanterTools.DatabaseConverter` |

- 組織の変数 `NUGET_ORG_USER`（公開用の共用アカウントの nuget.org プロフィール名。メールアドレスではない）を、このリポジトリへ共有する。未設定だと `publish-nuget` ジョブが明確なエラーで止まる
- `VehicleVision` の ID プレフィックスは予約済み（公開用の共用アカウント）

### 公開の流れと注意

- `release.yml` の `verify` ジョブが、配布 ZIP と同じ検査のあとに `dotnet pack` を行い、nupkg を成果物として上げる。PR と dry-run でも pack まで検証され、**push はしない**
- `publish-nuget` ジョブ（タグの push、または `dry_run=false` の手動実行だけで動く）が、nupkg の版とタグの一致を確認し、`NuGet/login` で 1 時間有効の API キーを受け取って `dotnet nuget push --skip-duplicate` を行う
- **公開した版は取り消せない**（nuget.org では削除できず、非推奨にできるだけ）。タグも付け直せない
- `v0.1.0` は GitHub Releases にだけある。nuget.org へは、準備の済んだあとの次の版から出る
- 初回は、タグを作る前に **dry-run を 2 つとも回す**。どちらも pack まで検証し、何も公開しない

  ```bash
  # タグ作成のワークフロー（版と起動ブランチの検証だけ。dry_run は既定が true）
  gh workflow run release-run.yml --ref develop
  # Release ワークフロー（検証・配布物の作成・pack まで。公開しない）
  gh workflow run release.yml --ref develop -f dry_run=true
  ```

- 公開後は、一覧に反映されるまで数分かかる。`dotnet tool install -g VehicleVision.PleasanterTools.DatabaseConverter --version <版>` で確かめる

## 公開前の確認

- `LICENSE` と `NOTICE` が現状と合っている
- nupkg の内容（`tools/net10.0/any/` に `DotnetToolSettings.xml`・実行物・Core、パッケージ直下に README・`LICENSING.md`・`LICENSE`・`LICENSE-COMMERCIAL.md`・`NOTICE`）が揃っている。ローカルでは `dotnet pack -c Release -p:Version=0.0.0-local -o <出力先>` で作り、`dotnet tool install --tool-path <先> --add-source <出力先> VehicleVision.PleasanterTools.DatabaseConverter --version 0.0.0-local` で入れて動作を見る
- nupkg に `Microsoft.Data.SqlClient.SNI.runtime`（Microsoft 独自の許諾）が含まれる。頒布条件は `LICENSING.md`・`LICENSE-COMMERCIAL.md`・`NOTICE` に反映済みであることを確認する
- 配布物に設定ファイル・秘密・参照ソース・Git メタデータが入っていない
  （`scripts/package.ps1` と `scripts/reference-isolation-check.sh` が検査する）
- 商用公開でデュアルライセンスにする場合は [ライセンス](ライセンス.md) の手順が済んでいる

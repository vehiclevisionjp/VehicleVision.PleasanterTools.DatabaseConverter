# 開発運用

## ブランチと PR

- `develop` が開発の本流、`master` がリリース確定用
- 作業ブランチは `develop` から分岐し、PR の base も `develop`
- Issue を作ってから変更し、PR 本文に `Closes #N` を書く
- 作業中は Draft とし、タイトルに `WIP:` を付ける。Draft 解除はレビュー可能、`WIP:` 除去はマージ可能の合図

## 定期実行

| 対象 | 頻度 | 仕組み |
| --- | --- | --- |
| Pleasanter 参照ソース（サブモジュール）の最新化 | 毎日 | `reference-submodule-update.yml` が上流の `Pleasanter_*` 最新タグと比べ、遅れていれば Issue と Draft PR を作る |
| NuGet・npm・Actions の依存更新 | 毎週 | Dependabot（`.github/dependabot.yml`）が `develop` 向けに PR を作る |
| 依存の脆弱性検査 | 毎週月曜と push | `dependency-audit.yml` |
| CodeQL と依存レビュー | 毎週日曜と push／PR | `codeql.yml`、`dependency-review.yml`。public か GHAS 有効のリポジトリだけで動く（下記） |

参照ソースの更新 PR は、サブモジュールのポインタだけを進める。`_reference/README.md` や `_documents/アーキテクチャ方針.md` が書いている「根拠にした版」は自動では書き換えない。新しい版で確認し直してから揃える。

## GitHub の初期設定

新しいリポジトリを作った直後に行う。

1. 既定ブランチを `develop` にする
2. `master` と `develop` にルールセットを設定する。定義は `.github/rulesets/protected-branches.json`、反映は `./scripts/Sync-Ruleset.ps1`（管理者権限が要る）。ブランチの削除と強制 push を禁止し、PR と必須チェック（`build-test`、`instructions`、`nuget-audit`、`npm-audit`）を要求する。CodeQL を動かすリポジトリでは `-IncludeCodeQL` を付けて `Analyze (csharp)` も必須にする。リポジトリの管理者は迂回できる（初期配置と緊急対応のため）
3. 参照ソースの更新用に GitHub App を使う。リポジトリ変数 `MY_REPO_AUTOMATION_BOT_CLIENT_ID` とシークレット `MY_REPO_AUTOMATION_BOT_PRIVATE_KEY` を登録する。App には Contents・Pull requests・Issues の書き込み権限が要る
4. 公開範囲に応じて CodeQL と依存レビューを切り替える。**public** のリポジトリは何もしなくてよい。**internal / private** は、コードスキャンと依存レビューに GitHub Advanced Security（GHAS）が要る。GHAS を有効にしたら、リポジトリ変数 `CODEQL_ENABLED` を `true` にする（`gh variable set CODEQL_ENABLED --body true`）。有効にしない間、この 2 つのジョブはスキップされ、リリースの確認もスキップを許容する
5. ラベルを作る。定義は `.github/labels.json`、反映は `./scripts/Sync-Labels.ps1`（gh CLI でログイン済みであること）。参照ソース更新の Issue は `1-owner:automation`、`2-type:dependencies`、`3-area:pleasanter` を使うため、無いと作成に失敗する
6. 「Template repository」にするのはテンプレート側のみ。派生したリポジトリでは外す

## 外部記憶

Claude や Codex が作業の知見を残す必要があるときは、`<リポジトリ名>.ClaudeMemory` の名前で Internal リポジトリを作って管理する。本体リポジトリへ記憶ファイルを置かない。

- 作ったら `CLAUDE.md` に URL を書く
- 作業ツリーはエージェントのメモリディレクトリそのものにし、別の clone を作らない（2 つあると片方が古くなる）
- 正式な規約の置き場所ではない。`.github/copilot-instructions.md` が常に優先され、食い違ったら記憶側を直す

## スクリプト

| スクリプト | 用途 |
| --- | --- |
| `scripts/New-FromTemplate.ps1` | テンプレートから名前を置換する |
| `scripts/Sync-Labels.ps1` | `.github/labels.json` のラベルを GitHub へ反映する |
| `scripts/Sync-Ruleset.ps1` | `.github/rulesets/protected-branches.json` のルールセットを GitHub へ反映する |
| `scripts/sync-agents.sh` | `AGENTS.md` を共通指示から生成・検査する |
| `scripts/reference-isolation-check.sh` | 参照ソースがビルドへ混ざっていないか検査する |
| `scripts/reference-submodule-check.sh` | 上流の最新タグと固定位置を比べる |
| `scripts/reference-submodule-open-pr.sh` | 更新の Issue と Draft PR を作る |
| `scripts/nuget-vulnerable-check.ps1` | 推移的依存を含めた脆弱性検査 |
| `scripts/package.ps1` | 配布 ZIP と SHA-256 を作る |
| `scripts/release-check.ps1` | タグと版の整合を検査する |
| `scripts/markdownlint.mjs` | Git 管理下の Markdown を検査する |
